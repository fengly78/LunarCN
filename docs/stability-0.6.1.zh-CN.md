# 0.6.1 稳定性验证

日期：2026-11-13。设备范围：当前 Apple Silicon Mac、macOS 27.2.1、DELL U3225QE。以下结果不能推广为所有显示器、扩展坞或 macOS 版本均已兼容。

## 修复与依据

- 休眠触发的 `1014`：真机复现了 `active=0, online=1, asleep=1` 时再次提交启用配置，约十秒后返回 1014。恢复流程现在先唤醒，并按在线状态区分休眠与断开。保护进程按实体外接屏是否在线判断连接，正常显示器休眠不会被误判为拔线。
- 恢复状态：重复恢复请求不再并发执行；迟到的 READY 不会覆盖已发出的恢复请求；确认恢复后清除旧错误提示。
- 中文消息：管道按字节缓存完整一行后再解码，避免中文字符跨数据块时乱码。
- DDC 未就绪：响应等待提高到 50 毫秒，无效读取最多五次，退避为 100／200／400／800 毫秒。查询与写入确认共用四秒预算，Swift 辅助进程超时继续兜底；无效回复不当作零亮度，也不因重试追加设置操作。写后读数独立确认，未确认仍失败并暂停。

## 本机通过的检查

| 检查 | 结果 |
| --- | --- |
| 已在线但休眠的内建屏恢复 | 约 0.36 秒，恢复后 active=1、online=1、asleep=0 |
| 内建屏保持关闭时显示器休眠 | 保护进程保持运行，不误触发恢复；主动恢复约 0.72 秒完成 |
| 修正 DDC 后关闭／恢复循环 | 12 次完成，60 次 DDC 命令全部确认，目标读数均为 59/100；最长命令约 2.05 秒 |
| GUI 异常退出恢复 | 保护进程约 0.61 秒内恢复内建屏 |
| 滑块即时调节 | 无需应用按钮，独立回读确认 46% 和反向调节的 44% |
| 自动跟随 | 内建屏 45.5%，外接屏回读 46%；源亮度随后恢复原值 |
| 重启与单实例 | 手动模式保留；重复启动仍只有一个 GUI 进程 |
| 输入与协议保护 | 错误 UUID、内建屏 DDC、越界值、未知控制码及溢出 ID 被拒绝；短报文、校验失败、重试耗尽、已过时间预算有自检覆盖 |

回归检查确认：去掉迟到 READY 保护或第五次读取，会使相应测试失败；中文错误逐字节传输在旧解析方式下也会失败。

## 显示器自身自动亮度

本机对照显示，Dell 自身自动亮度开启时会把手动目标持续覆盖，曾从 59 回落至 58、42、25、3；关闭后上述循环保持目标值。该冲突与 DDC 未就绪是不同问题。

使用月光手动亮度或跟随内建屏时，请先在显示器菜单关闭显示器自身自动亮度。月光不会在后台自动改动该传感器设置。Dell 官方也说明该型号具有自身环境光调节，并记录过相关固件问题：[官方说明](https://www.dell.com/support/kbdoc/en-us/000356362/dell-ultrasharp-monitors-may-exhibit-various-issues?lang=en)。本次未更新固件，不能据此断定具体固件版本存在缺陷。

## 验收边界

本次是显示器休眠与唤醒测试，不是整机睡眠测试。真实拔线、合盖、多台外接屏同时拖动、Intel、其他显示器和扩展坞尚未验收。已修复的是本次复现的 1014 触发路径，不保证其他系统或硬件条件不会返回同一错误码。

应用仍使用本机临时签名，未经 Developer ID 签名或 Apple 公证；这是试用版，不宣称没有 Bug。
